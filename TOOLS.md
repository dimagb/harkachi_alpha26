# Инструменты тимлида — памятка для вас

Коротко: почти всё тимлид вызывает сам. От вас нужны три вещи: поставить плагины, когда он попросит; вводить встроенные команды Claude Code, которые он запустить не может; при желании — вызвать инструмент вручную.

## Что есть что

| Вид | Что это | Где живёт | Кто ставит |
| --- | --- | --- | --- |
| **Плагин** | Пакет от Anthropic или вендора: скиллы, команды, хуки. Например, `superpowers`, `code-review` | На вашем аккаунте Claude Code, не в репозитории | Вы, командой `/plugin install` |
| **Скилл** | Инструкция для типовой работы, подгружается, когда нужна | Скиллы плагинов — внутри плагина; наши (`product-brainstorming`, `write-spec`) — в `.claude/skills/` | Плагинные — с плагином; наши уже в архиве |
| **Субагент** | Отдельный помощник со своим чистым контекстом и задачей: `critic`, `researcher`, `reviewer` | `.claude/agents/` | Уже в архиве |
| **MCP** | Подключение внешнего источника, например актуальной документации (`context7`) | На вашем аккаунте | Вы, командой из `SETUP.md` |

Плагины не лежат в архиве, потому что ставятся на аккаунт. Тимлид ими пользуется: `superpowers`, `code-review` и `commit-commands` нужны сразу, остальные — по этапам.

## Порядок установки

| Когда | Что поставить | Команда |
| --- | --- | --- |
| До первого запуска | `superpowers`, `code-review`, `commit-commands` | `/plugin install superpowers@claude-plugins-official` и так же два других |
| Этап 3 (модель решения) | MCP `context7` | `npx ctx7 setup --claude` в терминале |
| Этап 3–4 (бриф дизайна) | `frontend-design` | `/plugin install frontend-design@claude-plugins-official` |
| Этап 5 (разработка) | `security-guidance` | `/plugin install security-guidance@claude-plugins-official` |
| Этап 5–6 (проверка прототипа в браузере) | Playwright CLI | `npm install -g @playwright/cli@latest`, затем `playwright-cli install --skills` |
| Этап 6 (аудит перед сдачей) | `trailofbits/skills` | `/plugin marketplace add trailofbits/skills`, затем `/plugin` → вкладка Discover → нужный плагин этого каталога |

Как ставить:

1. `/plugin install …` открывает карточку плагина. Посмотрите, что он добавит и сколько токенов займёт («Context cost»).
2. Выберите **Install for you (user scope)**.
3. Если в конце написано `Run /reload-plugins to apply`, введите `/reload-plugins`.
4. Проверка: `claude plugin list` в терминале или вкладка **Installed** в `/plugin`.

Ставить всё сразу не нужно: каждый плагин занимает контекст в каждом сообщении. Тимлид сам проверяет установленное в начале этапа и напомнит, если чего-то не хватает.

## Что тимлид делает сам

| Когда | Что вызывает |
| --- | --- |
| Развилка, которую нужно обсудить с вами | `superpowers:brainstorming` |
| Исследуем проблему пользователя и проверяем идеи | `product-brainstorming` |
| Фиксируем MVP или функцию | `write-spec` |
| Нужен пошаговый план | `superpowers:writing-plans` |
| Нужно поискать и прочитать много страниц | субагент `researcher` (работает на Sonnet, дешевле) |
| Перед каждыми воротами | субагент `critic` |
| Ревью PR | `/code-review`, для крупных — субагент `reviewer` |
| Перед словом «готово» | `superpowers:verification-before-completion` |

Вам не нужно ничего прописывать. Если вызова не было, а вы считаете, что он нужен, скажите об этом — это нормальная часть работы.

## Как вызвать вручную

| Что | Как написать |
| --- | --- |
| Наш скилл | `/write-spec MVP кабинета` или `/product-brainstorming` |
| Скилл плагина | `/superpowers:brainstorming`, `/superpowers:writing-plans` |
| Субагент, гарантированно | `@agent-critic проверь docs/mvp.md` (можно выбрать из подсказки после `@`) |
| Субагент, обычной фразой | «Попроси critic проверить архитектуру» |
| Команда плагина | `/code-review`, `/commit` |

Список всего доступного появляется, если ввести `/`. Субагенты — в меню `/agents`.

## Что можете только вы

Эти встроенные команды Claude Code тимлид запустить не может, он попросит вас:

| Команда | Зачем |
| --- | --- |
| `/compact` | Сжать разговор на границе этапа, когда тимлид обновил `docs/STATE.md`. Экономит лимит. Можно добавить подсказку, что сохранить: `/compact Сохрани: решения этапа и открытые вопросы` — тимлид обычно даёт готовую команду. Важное всё равно лежит в файлах, а хук проекта после любого сжатия сам возвращает тимлиду `STATE.md` |
| `/clear` | Начать с чистого листа (затем «продолжаем» — тимлид прочитает `STATE.md`) |
| `/model` | Сменить модель. Тимлиду — Opus; для простой механической работы можно временно Sonnet |
| `/plugin`, `/reload-plugins` | Ставить и применять плагины |
