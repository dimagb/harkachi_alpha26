

| Вопрос | Ответ |

| 1\. Можно ли моделировать подписание согласий и кредитного договора электронной подписью с подтверждением кодом внутри интерфейса, без SMS? Будет ли плюсом описание интеграции с ДБО и Госключом в промышленной версии? | Да, подписание можно смоделировать внутри продукта без реальных SMS и внешних сервисов. Описание того, как процесс будет устроен в промышленной версии, может дополнительно усилить обоснование решения, но не гарантирует дополнительных баллов. |
| 2\. Можно ли дополнительно предоставить ссылку на развёрнутое демо на собственном сервере, где открытая модель работает через API? | Да, дополнительное онлайн-демо допускается, в том числе на платном VPS. При этом должна сохраняться возможность самостоятельно запустить и проверить основное решение локально по инструкции. |
| 3\. Подойдет ли один веб\-интерфейс с двумя ролями и тестовыми учетными записями клиента и кредитного специалиста? | Да, два отдельных приложения не требуются. Количество интерфейсов и ролей команда определяет самостоятельно. Главное — продемонстрировать связанный клиентский и банковский процесс. |
| 4\. Какая конфигурация компьютера будет использоваться при проверке? Сколько оперативной памяти, будет ли GPU и интернет? | Ориентир около 12 ГБ оперативной памяти для серверной части в состоянии простоя. Для клиентской части — обычный офисный ноутбук с 8 ГБ RAM. Интернет на время проверки будет, на наличие GPU желательно не ориентироваться. |
| 5\. Можно ли скачивать веса модели при первом запуске или необходимо включать их в репозиторий? | Допускается скачивание весов моделей из интернета при первом запуске. Хранить веса непосредственно в репозитории необязательно. Главное — указать источник модели и подробно описать процесс загрузки и запуска в README, чтобы эксперты могли самостоятельно воспроизвести решение |
| 6\. Можно ли использовать логотип и фирменный стиль Альфа-Банка? | Да, использовать фирменный стиль и логотип Альфа-Банка разрешено. Также допускается собственный визуальный стиль. Обязательной дизайн-системы нет. |
| 7\. Где лучше хранить веса самостоятельно обученной или дообученной модели: Git LFS или внешнее хранилище? | Команда самостоятельно выбирает способ хранения, обеспечивающий воспроизводимый запуск решения. Проверяемая версия не должна зависеть от платных ресурсов |
| 8\. Как должны распределяться права между собственником, директором, бухгалтером и сотрудниками по доверенности? Насколько глубоко учитывать юридические полномочия? | Обязательная модель разграничения полномочий не установлена. Команда самостоятельно определяет необходимые роли и глубину их реализации в рамках выбранного MVP. Юридически сложные процессы допускается моделировать с описанием принятых упрощений. |
| 9\. Как должен различаться маршрут кредитной заявки для разных продуктов — от краткосрочного кредита до крупного финансирования с залогом? | Команда самостоятельно определяет этапы, проверки и набор данных для выбранных продуктов. Важно обосновать логику и сохранить связность кредитного процесса |
| 10\. Когда запрос дополнительной информации, встречное предложение или повторная подача после отказа должны происходить в рамках существующей заявки, а когда создавать новую? | Команда самостоятельно проектирует переходы между состояниями заявки и обработку разных исходов. Важно, чтобы данные сохранялись, а изменение статусов соответствовало реализованной бизнес-логике. |
| 11\. Как клиент должен передавать данные о компании в систему? | Через реализованный личный кабинет клиента. Состав полей и способ получения данных команда выбирает самостоятельно. Допускается использование заранее подготовленных синтетических данных и демонстрационных профилей. |
| 12\. Нужны ли презентация, видеопитч или запись демонстрации для отборочного этапа? | Нет, для отборочного этапа презентация и видеопитч не требуются. Необходимо предоставить работающее решение и предусмотренные кейсом материалы для его проверки. |
| 13\. Обязательно ли делать личный кабинет и для банка, и для предпринимателя? | Личный кабинет с веб\-интерфейсом обязателен для клиента. Банковская обработка заявки также должна быть реализована. |
| 14\. Можно ли разработать независимый сервис, который только косвенно связан с кредитными продуктами и встраивается в экосистему Альфа-Банка? | Дополнительный сервис реализовать можно, но он не заменяет основную задачу. Решение должно демонстрировать работающий кредитный конвейер, связывающий клиентский путь с обработкой заявки и получением результата. |
| 15\. Можно ли развернуть решение на собственном сервере или облачном хостинге? | Да, можно использовать собственный сервер, любого облачного провайдера, в том числе с бесплатным тарифом, либо платный VPS. Необходимо сохранить возможность локального воспроизводимого запуска через Docker. |
| 16\. Можно ли получить доступ к Альфа-ИИ? | Нет, организаторы не предоставляют ключи и доступ к корпоративным ИИ-сервисам Альфа-Банка. При использовании моделей необходимо соблюдать требование об открытых весах и обеспечить возможность настройки стороннего OpenAI-совместимого провайдера. |
| 17\. Можно ли показывать клиенту внутренний процесс одобрения кредита на стороне банка, включая текущий этап рассмотрения? | Система должна отражать движение заявки по этапам, сохранять ее состояние и показывать изменения статуса. Глубину раскрытия внутренних банковских процессов команда определяет самостоятельно. |
| 18\. Что важнее: создать инновационное решение или улучшить существующий кредитный процесс и его показатели? | Допускаются оба подхода. Эксперты оценивают целостность, работоспособность, пользовательскую ценность и обоснованность решений. Новизна сама по себе не заменяет качественную реализацию основного сценария. |
| 19\. Можно ли использовать готовые открытые решения, библиотеки и компоненты? | Да, допускаются готовые компоненты, модели и no-code/low-code-инструменты. Команда должна понимать архитектуру решения, обеспечить его работоспособность и перечислить сторонние компоненты в документации THIRD\_PARTY\_NOTICES. |
| 20\. Допустима ли разработка с помощью ИИ, в том числе вайбкодинг? | Ограничений на использование ИИ-инструментов при разработке нет. Допускаются и платные инструменты разработки, если проверяемая версия от них не зависит |
| 21\. Какова главная цель кредитного конвейера: удобство получения финансирования клиентом или сокращение затрат банка и ускорение обработки заявок? | Важны обе стороны процесса. Решение должно помогать предпринимателю пройти путь получения финансирования и одновременно обеспечивать эффективную обработку заявки со стороны банка. Приоритет конкретных продуктовых показателей команда определяет самостоятельно. |
| 22\. Входят ли ООО и другие юридические лица в целевую аудиторию? Какие границы малого и микробизнеса использовать? | Да, целевая аудитория включает действующих индивидуальных предпринимателей и юридические лица. Физические лица, только планирующие открыть бизнес, не являются основным сегментом кейса. Отдельные количественные границы не установлены; при выборе сегмента можно опираться на действующее законодательство. |
| 23\. Можно ли подготовить описание решения с помощью ИИ или текст должен быть написан командой самостоятельно? | Способ подготовки текста документации не регламентирован. Важно, чтобы предоставленные материалы достоверно описывали реализованное решение, его архитектуру, требования и сценарии проверки. |
