# Экраны и тексты — бриф для дизайна (D6) и фронтенда

Пользователь — предприниматель или бухгалтер **без банковской экспертизы**. Главная задача каждого экрана — ответить на три вопроса: где моя заявка, что происходит, что от меня нужно (F24). Десктоп — основной (Q14). Тексты ниже — рабочие; меняет только тимлид или человек.

## 1. Эстетическая рамка (предложение тимлида — человек правит в Claude Design)

- **Характер:** спокойная уверенность банка, а не маркетинговый лендинг. Свой стиль, близкий к Альфе: красный — только для главного действия, всё остальное сдержанное.
- **Цвета (токены):** `ink #1F2329` (текст), `paper #FFFFFF` (фон), `surface #F2F3F5` (подложки), `signal #E8302A` (главная кнопка, активный этап; близко к Альфе, не копия), статусы: `ok #1E8E5A` (одобрено, выдано), `wait #C77700` (нужно ваше действие), `flow #4A6178` (идёт обработка), `stop #B42318` (отказ — не тот же красный, что у кнопки).
- **Шрифт:** одна семья с хорошей кириллицей — **Onest** или **Golos Text** (оба бесплатные, Google Fonts). Деньги — с табличными цифрами (`font-variant-numeric: tabular-nums`), формат `1 500 000 ₽`.
- **Одна запоминающаяся вещь — лента этапов заявки.** Крупная горизонтальная полоса из шести этапов на каждом экране заявки; под активным этапом — «Что происходит» и «Что от вас нужно» с кнопкой. Всё остальное тихое: без градиентов, без одинаковых карточек с тенью, без декоративных иконок.
- **Анимация:** только одна — переход этапа на ленте, когда статус меняется (заявка «едет» по конвейеру). Остального движения нет.
- **Чего избегать:** надписи капслоком над заголовками, «→» в кнопках, одинаковое скругление на всём, кремовый фон.

## 2. Правила текста
- Глаголы в кнопках говорят, что произойдёт: «Отправить заявку», «Подписать договор», «Принять предложение». Действие и результат называются одинаково: «Подписать» → «Подписано».
- Без банковского жаргона: «платёж в месяц», а не «аннуитет»; «проверяем данные», а не «верификация»; ПСК не показываем (B2B).
- Отказ и ошибка — без извинений и без расплывчатости: что случилось → что сделать → когда можно снова.
- Предложения и формы — с заглавной только первое слово.

### Ключевой 1 — карточка заявки
```
┌───────────────────────────────────────────────────────────────┐
│ Экспресс-кредит · 1 500 000 ₽ на 24 мес.        Заявка № 1042 │
│                                                               │
│  ●───────●───────◉───────○───────○───────○                    │
│  Заявка  Проверка Оценка  Решение Подписание Выдача           │
│                                                               │
│  Что происходит: оцениваем заявку по данным о вашем бизнесе.  │
│  Что от вас нужно: ничего, обычно это занимает пару минут.    │
├───────────────────────────────┬───────────────────────────────┤
│ Параметры заявки              │ История                       │
│ Цель, сумма, срок, платёж     │ 14:02 Заявка отправлена       │
│ Компания (из реестра)         │ 14:02 Данные проверены        │
│ [Отозвать заявку]             │ 14:03 Сведения получены       │
└───────────────────────────────┴───────────────────────────────┘
```
Тексты этапов — `state-machine.md`, «Состояния → этапы ленты». Состояние «нужно ваше действие» окрашено `wait` и даёт кнопку прямо под лентой («Ответить на вопросы банка», «Подписать договор»).

### Ключевой 2 — решение (три варианта)
- **Одобрено.** Заголовок: «Банк одобрил 1 500 000 ₽». Условия: ставка, срок, платёж в месяц, до какого числа действует предложение. Блок «Почему одобрили»: 2–3 сильные стороны («Стабильные обороты по счёту», «Нет просрочек»). Кнопки: «Принять предложение», «Отказаться».
- **Встречное.** Заголовок: «Банк готов выдать 2 850 000 ₽ на 24 месяца». Пояснение: «Запрошенная сумма даёт слишком высокую нагрузку на ваши обороты: платежи заняли бы больше 30% поступлений. Мы подобрали сумму и срок, при которых платёж посилен». Сравнение «Вы просили / Мы предлагаем». Кнопки: «Принять предложение», «Отказаться».
- **Отказ.** Заголовок: «Банк не может выдать кредит сейчас». Блок «Причина» — категория и текст из `decision-model.md` §3; «Что можно сделать» — действие и дата повторной подачи. Для ИП при авто-решении: «Не согласны с решением? Его пересмотрит специалист банка» → «Попросить пересмотр». Без ссылок на законы и внутренние проверки; для `ADDITIONAL_CHECKS` — только нейтральный текст.

### Ключевой 3 — карточка андеррайтера
```
┌──────────────────────────────────────────────────────────────────┐
│ ООО «ТехноМонтаж» · Экспресс 2 000 000 ₽ / 24 мес.   Ждёт 12 мин │
│ Почему у вас: пограничная оценка (C, 58 баллов)                  │
├──────────────────────────────┬───────────────────────────────────┤
│ Факторы оценки               │ Рекомендация системы              │
│ Срок бизнеса  14 мес.   +10  │ Встречное: 1 500 000 ₽ / 24 мес.  │
│ Обороты CV 0,5          +10  │                                   │
│ Нагрузка PTR 22%         +5  │ Решение                           │
│ Кредитная история       +20  │ ○ Одобрить  ○ Встречное           │
│ Налоги                  +10  │ ○ Отказать  ○ Запросить данные    │
│ Отрасль                  +3  │ Комментарий (обязательно)         │
├──────────────────────────────┤ [Принять решение]                 │
│ Сведения: ЕГРЮЛ ✓ БКИ ✓ ФНС ✓│                                   │
│ Обороты за 12 мес. (график)  │                                   │
└──────────────────────────────┴───────────────────────────────────┘
```
Схема выше упрощена: в продукте факторы — 12 признаков в 5 группах (`decision-model.md` §4, промпт 4 в `design/claude-design-prompts.md`), у `ooo_border` — 54 балла, C. Андеррайтер видит всё, включая внутренние флаги. Если его решение расходится с рекомендацией, ставится пометка в журнале.
