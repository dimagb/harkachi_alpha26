# Коллекция API кредитного кабинета

Коллекция Bruno для проверки требования T9 без интерфейса: вход, подача
заявки, дозапрос, ручное решение и выдача кредита. Тела запросов и ожидаемые
суммы взяты из `contracts/personas.json`, пути и поля — из контрактов API.

## Запуск

Нужны Node.js 22 или новее и запущенный стенд. Из корня репозитория:

```powershell
docker compose up -d
cd docs/api-collection
npx --yes @usebruno/cli@4.3.0 run --env local
```

Зафиксирована стабильная версия **@usebruno/cli 4.3.0** (MIT). Первая команда
`npx` загружает CLI из npm; последующие используют кеш. Сами запросы идут
только на локальный стенд. Дождитесь готовности API на
`http://localhost:8080/api/v1/health`, если стенд только что запущен.

Можно установить эту же версию глобально:

```powershell
npm i -g @usebruno/cli@4.3.0
bru run --env local
```

Успех: все запросы и тесты зелёные, код выхода `0`. Ожидаемые HTTP 401,
403, 409 и 422 в разделе ошибок считаются успешными проверками.

## Открыть в Bruno

В приложении Bruno выберите **Open Collection** и папку `docs/api-collection`
с файлом `bruno.json`. Выберите окружение **local**, затем **Run Collection**.
Запускайте всю коллекцию последовательно, в порядке `01`–`06`: поздние
запросы используют результаты предыдущих. Параллельный запуск не подходит.

## Что проверяют разделы

| Раздел | Проверки |
| --- | --- |
| `01-service` | Доступность API и три кредитных продукта. Перед каталогом скрипт выполняет запрос входа `02-login/01-ip_good`, поскольку каталог доступен клиенту. |
| `02-login` | Восемь демо-учёток, токены и роли; `/me` проверяет компанию ИП и сохраняет её ID. |
| `03-ip_good-full-path` | Новая заявка, согласия через OTP, оферта 1 500 000 ₽ / 24 мес. / 22 % / 77 817 ₽, принятие, подпись своей стороной и выдача. |
| `04-ooo_gap-info-request` | Новая заявка ООО, запрос подтверждения выручки, ответ и оферта 1 000 000 ₽ / 24 мес. / 22 % / 51 878 ₽. |
| `05-underwriter` | Новая заявка `ooo_border`, очередь с причиной `GRADE_C`, 54 балла и 12 факторов, ручное одобрение; клиенту — 1 000 000 ₽ / 24 мес. / 26 % / 53 875 ₽. |
| `06-errors` | Неверный пароль, недоступная клиенту очередь, старая версия оферты и сумма вне продукта. |

Каждый запуск создаёт три новые заявки. ID компаний, заявок, версий оферт,
сторон подписи и OTP берутся из ответов. Очередь проверяется по ID новой
заявки, поэтому существующие заявки не мешают и чистить стенд не нужно.

Решение ожидается до 60 секунд, выдача — до 30 секунд. Запросы ожидания
повторяют себя через `bru.runner.setNextRequest` с паузой `await bru.sleep(1000)`;
таймер общий для всех попыток. При неожиданном состоянии или истечении
времени проверка падает. Все вызовы выполняются стандартными средствами
Bruno в режиме Safe Mode, без внешних библиотек.

Токены и OTP сохраняются только в переменных выполнения через `bru.setVar`,
на диск не записываются. Демо-пароль задан только в `environments/local.bru`.
Не сохраняйте ответы входа и отчёты с заголовком Authorization в git.

Документация: [CLI](https://docs.usebruno.com/bru-cli/overview),
[скрипты и переменные](https://docs.usebruno.com/testing/script/javascript-reference).
