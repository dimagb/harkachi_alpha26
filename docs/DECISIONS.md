## 2026-10-22 — D2. Условное правило: ЕСЛИ возьмём LLM — открытые веса, сменный провайдер, основной сценарий без LLM {#d2}

- **Важно:** использовать ли LLM или ML, НЕ решено. Это развилка этапа 2. Предварительная рекомендация тимлида — скоринг и решение на правилах и балльной модели (см. STATE.md).
- **Решение (допущение):** если используем LLM/OCR — только модели с открытыми весами, провайдер настраивается через base URL, токен и имя модели. Основной сквозной сценарий должен работать и без доступной модели.
- **Почему:** `case.md` (Ограничения, п. 2 и 8) запрещает зависимость от платных API и требует открытых весов; `webinar-qa-1.md` в. 20, 23, 39 разрешают сторонний и даже платный API, если веса открыты и провайдер меняется. Сводим это так: на проверке жюри подставит своего провайдера, а если не подставит или он недоступен, основной сценарий не должен ломаться. Сервер на проверке без GPU, ~12 ГБ ОЗУ (`webinar-qa-2.md` в. 4).
- **Отвергнуто:** LLM как обязательное звено основного сценария.
- **Утвердил:** принято без подтверждения.
