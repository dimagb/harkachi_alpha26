## 2. Задачи аудита
**A-07 «Покрытие автомата» (Codex, ≤1 ч, 25.10):** по БД стенда после A-03 + F-09 — тройки `(из, в, actor)` из `application_event` против таблицы переходов `state-machine.md` → «покрыто / не покрыто»; тупики — состояния, где у клиента `allowed_actions = []`, у банка нет действия и нет перехода по времени (кроме финальных). Отчёт — `docs/audit/state-coverage.md`.

**A-08 «Обход интерфейса» (Codex, ≤1 ч):** Playwright по всем маршрутам обеих ролей и кнопкам, не меняющим данные: ошибки консоли, ответы 4xx/5xx кроме ожидаемых, битые ссылки, горизонтальный скролл на 375, тексты «undefined»/«NaN»/пустые, **коды вместо текста** (`^[A-Z_]{3,}$` в видимом тексте), шестнадцатеричные цвета в `src`. Плюс (стандарт WCAG 2.1 AA): **axe-core** на каждом экране — 0 нарушений `critical`/`serious`; путь «вход → подача → подпись» с клавиатуры, фокус виден. Плюс Firefox и окно 1366×768 (ноутбук жюри).

**A-09 «Безопасность и устойчивость API» (Codex, ≤1,5 ч, 25.10, на стенде) — по OWASP API Security Top 10 (2023) и требованию T17 «enterprise-подход»:**
1. **Доступ к чужим объектам (API1, BOLA):** матрица «каждый эндпоинт × роль (клиент своей компании, клиент чужой, бухгалтер без подписи, андеррайтер, без токена, просроченный/подделанный токен)» → ожидаемые 401/403/404; автотест в `tests/e2e/api/test_access_matrix.py`.
2. **Фаззинг по контракту (T8 «OpenAPI совпадает с реализацией»):** Schemathesis против стенда по `openapi.json` — нет ответов 500, ответы соответствуют схеме. Запуск `uvx schemathesis`, в зависимости проекта не добавлять.
3. **Утечки:** 500 не отдаёт трассировку и SQL; клиентские ответы всех эндпоинтов без внутренних полей (`score`, `rules_fired`, `comment`, `made_by`, `SF_ADDITIONAL`) — расширить тест `ooo_aml` на все клиентские GET/POST.
4. **Секреты:** `gitleaks` по всей истории репозитория (токен Telegram уже засвечивался); найденное — отозвать и описать.
5. **Уязвимые зависимости:** `npm audit --omit=dev` и `uvx pip-audit` — `high`/`critical` обновить или объяснить в отчёте.
6. **Повторы и гонки:** двойная отправка `submit`, `offer/accept`, `sign`, `decision` (два запроса параллельно) → одно действие, второй — 409; перезапуск `worker` посреди конвейера (`docker compose restart worker`) → заявка доходит до решения.
7. **Автономность (T14):** после сборки образов стенд стартует и проходит `ip_good` с отключённой сетью.
8. **ПДн и логи (152-ФЗ):** в логах `api`/`worker` после прогона A-03 нет паролей, кодов OTP, токенов; `demo_code` и `time-shift` только при `DEMO_MODE=true` (тест с `false`).
Отчёт — `docs/audit/security.md`: проверка → результат → что сделали.
