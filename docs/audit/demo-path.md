Разрешённых 4xx нет. Суммы, ставки, платежи, параметры заявок и ответ на дозапрос читаются из `contracts/personas.json`.

F-09b: аудит исключает из ошибок только сообщения `Loading the script 'URL' violates the following Content Security Policy`, если URL скрипта имеет другое происхождение (схема, хост или порт), чем `baseURL` стенда. Это учитывает скрипты антивирусов и расширений, которые CSP корректно блокирует. Сообщения сохраняются в списке `ignored` вложения `browser-api-audit`; обычные ошибки приложения, CSP для скриптов стенда, других ресурсов и нераспознанных URL остаются ошибками. Самопроверка `00-audit-filter.e2e.ts` вставляет настоящий чужой скрипт на странице входа и проверяет успешный `check()`. Отдельный процесс с той же fixture проверяет через `toThrow` ошибки приложения и защитные границы фильтра; основной тест проверяет его отчёт и падение завершающего аудита. ## Найденные проблемы и вопросы тимлиду

1. **B-15: исправлена в PR #56, повторно проверена.** Ранее участники сортировались по случайному UUID и первым могло предлагаться поручительство. После rebase test.fail и устаревший TODO удалены. Проверка порядка сохранена и дополнена отсутствием кнопки поручительства до подписи договора. Обе новые заявки (`7ffa39b0-46e7-4b1c-855a-8d0988491bfa`, `a295c74e-7ad0-4761-aa45-937a127ccc54`) прошли договор → поручительство → выдачу. Вопрос закрыт.
2. **F-15: существующий тест, не F-09.** Два полных прогона: `1 failed | 328 passed (329)`, 23 файла; отдельно тот же файл: `1 failed | 13 passed (14)`. Падает `src/screens/NewApplication.test.tsx` → «серия вводов вызывает один расчёт через 400 мс с последней суммой»: `bodies=[]` вместо одного запроса калькулятора. В первом полном прогоне 19,53 с, во втором 16,72 с, отдельно 14,37 с. Тимлид подтвердил воспроизведение на чистом main под Windows; CI на Linux зелёный, заведена F-15. Код приложения и существующий тест не менялись. QUESTION отправлен, ответ получен. Весь локальный vitest зелёным не считается.
3. **Перемотка и возврат в окно — особенность headless, не ошибка.** Автообновление без действия клиента не требуется — уточнение оператора. В сценарии вызываются `bringToFront()` и `document.dispatchEvent(new Event('visibilitychange'))`, затем ожидание до 10 с. При необходимости сохранён reload; после него корректно видны «Срок истёк», «Подать новую заявку», старые кнопки отсутствуют. Каждый fallback сопровождается аннотацией finding и снимком до reload. Сценарий 7 при повторе после B-15 оставлен без изменений.
