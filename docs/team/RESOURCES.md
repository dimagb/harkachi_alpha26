# Ресурсы команды — справочник для этапа 4

Факты о том, чем располагает команда, и что умеют инструменты. Это вход для решения о ролях и методике, а не само решение. Уточни у человека то, что помечено «уточнить».

## Люди и аккаунты

| Ресурс | Кто пользуется | Факты |
| --- | --- | --- |
| 1 аккаунт Claude: Claude Code, Claude Design, чат | Ведущий участник (твой собеседник) | Лимит общий у всех сессий Claude Code, Claude Design и чата. Ты (тимлид) работаешь на нём же. Тариф — уточнить |
| 3 аккаунта ChatGPT с Codex | Другие участники, на их компьютерах | У ведущего нет прямого доступа к этим компьютерам: управлять можно только через людей, репозиторий и общий чат |
| Telegram | Вся команда | Планируется как общий канал людей и агентов |
| GitHub | Вся команда | Репозиторий с историей коммитов обязателен для сдачи |

Уточнить у человека: сколько людей в команде и их сильные стороны, сколько часов в день каждый готов держать своего агента, дедлайн, тариф Claude, есть ли VPS для демо.

## Соображения из подготовки (не решение)

- Самая затратная по лимиту роль — непрерывное написание кода (обычно бэкенд). Исследование и проектирование тратят много в начале, затем меньше; ревью и сдача снова требуют внимания тимлида. Риск: если лимит Claude кончится в разгар разработки, команда теряет тимлида.
- Качество модели сильнее всего влияет на решения (модель процесса, контракты, границы MVP); по точному контракту код уверенно пишут и Claude, и Codex.
- Управление через чат закрывает координацию (задачи, вопросы, уточнения, статусы), но не то, что требует рук у чужого компьютера: подтверждение команд агента, перезапуск остановившейся сессии, сброс переполненного контекста. Поэтому у каждого Codex нужен человек-оператор.
- Контроль качества надёжнее всего через GitHub (PR, CI, запуск в Docker), а не через доклады агентов в чате.
- Автоматическая связь между агентами полезна для узких вопросов (форматы полей, готовность эндпоинта, изменения контракта) и опасна для архитектурных решений: те должны проходить через тимлида и человека.

## Что умеют инструменты

**Claude Code** (ты и, возможно, другие сессии): `CLAUDE.md` и `AGENTS.md` как правила проекта; скиллы (`.claude/skills/`); субагенты (`.claude/agents/`, можно задать модель, например Sonnet для экономии); хуки (старт сессии, после действия, остановка — могут подмешивать контекст и продолжать работу); MCP-серверы; плагины.

**Codex** (ChatGPT): правила проекта из `AGENTS.md` от корня до рабочей папки; скиллы того же формата `SKILL.md` в `.agents/skills/` (репозиторий) и `~/.agents/skills/` (личные), вызов `$имя` или неявно по описанию ([документация](https://learn.chatgpt.com/docs/build-skills)); хуки с теми же событиями ([документация](https://learn.chatgpt.com/codex/hooks)), их нужно доверить через `/hooks`; MCP через `codex mcp add` или `~/.codex/config.toml` ([документация](https://developers.openai.com/codex/mcp)); неинтерактивный запуск `codex exec`; встроенное ревью кода. Для работы с соседними папками и сетью Codex запускают в корне клона с сетью песочницы.

**Готовые методики командной разработки**, которые стоит рассмотреть как альтернативу собственной: `github/spec-kit` (спецификация → план → задачи → реализация, работает с несколькими агентами), `BMAD-METHOD` (роли аналитика, PM, архитектора). Обе тяжёлые и задают свои правила — сравни с более простой собственной схемой.

**Заготовка связи через Telegram** — `drafts/telegram-bus/`: хаб на одном боте, адресная доставка сообщений агентам, хуки для Claude Code и Codex, доска прогресса. Сделана при подготовке и проверена на тестах, но не принята: решите вместе с человеком, нужна ли она в этом виде.
