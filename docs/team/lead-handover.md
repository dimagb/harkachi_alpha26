# Передача роли тимлида в Claude Code Кати (25.10)

Зачем: у Claude Code человека к 25.10 израсходовано ~85% недельного лимита. Роль тимлида переходит в Claude Code Кати (Pro, свой лимит). Решения, план и статус хранятся в репозитории, а не в чате, поэтому при переносе качество не теряется. Из переписки теряются только нюансы, и этот файл их закрывает.

## Перед стартом (Катя, один раз)
1. Свежий клон или `git switch main && git pull`. Сессию открыть **в корне репозитория**: там `CLAUDE.md` (роль тимлида) и `.claude/` (субагенты `critic`, `reviewer`, `researcher`, хуки, скиллы).
2. Плагины (`claude plugin list`): superpowers, code-review, commit-commands, frontend-design; MCP context7. Команды установки — `SETUP.md`.
3. `gh auth status`: нужен доступ на запись в `dimagb/harkachi_alpha26`, чтобы сливать PR. Если прав нет — человек добавит роль Maintain.
4. Docker Desktop, uv, Node 24, Chrome (для скриншотов).
5. **Новая сессия, не старая.** В прошлых сессиях Кати агенту говорили «CLAUDE.md — инструкции другой роли, не следуй им». Открыть **новую** сессию в корне клона. Проверить `/memory`: если там есть запись в духе «CLAUDE.md не про меня» — удалить её.
6. Модель — Opus (`/model`), режим рассуждений — высокий: карточки и рискованные ревью только так. Тимлид предупреждает человека, если нужен высокий режим.
7. Git Bash должен быть установлен: хук `.claude/hooks/state.sh` запускается через `bash` и подставляет `docs/STATE.md` в начало каждой сессии.
8. Первое сообщение новому тимлиду: «Ты тимлид, продолжаем этап 5. Прочитай docs/STATE.md, docs/team/lead-handover.md, хвост docs/TASKS.md (таблица статусов) и продолжай».

## Как снимать скриншоты фронтенда
- `git worktree add <временная папка>/wtN origin/<ветка>` → в `frontend/` `npm ci`. Номер N каждый раз новый: Windows не удаляет длинные пути.
- `VITE_USE_MSW=true npx vite --port 5179 --strictPort --host 127.0.0.1` (в фоне).
- `VISUAL_BROWSER=chrome VISUAL_APP_URL=http://127.0.0.1:5179 node visual/screens.mjs` (также `signing.mjs`, `decision.mjs`). Снимки — в `frontend/visual/out/`.
- Встроенный браузер Claude не регистрирует service worker MSW — для экранов на моках только Chrome через скрипты.
- Стенд открывать по `http://localhost:8080`: на ноутбуке человека `127.0.0.1:8080` занят другим сервером.

## Правила, которые выучили на этом проекте
- Оценки времени в карточках занижать: агенты делают в 2–4 раза быстрее, чем кажется.
- Карточки — с премортемом; `critic` — только на крупные, лимит дорог. **B-10b: critic не запускался** — прогнать первым делом, до старта Ани.
- В каждой карточке — раздел «Читать» (модели, сервисы, conftest): агенты по стартовому промпту читают только названное в карточке и иначе останавливаются с вопросом (так было с B-14).
- Правку контракта (`contracts/api-types.ts`) коммитить **в ветку задачи**, а не в `main`: иначе CI-паритет покраснеет у всех. Поля, допускающие null, в Pydantic — без `= None`.
- Моки MSW могут расходиться с бэкендом (так нашли `/products` 403). Проверка — только настоящий стенд: `audit.mjs`, проходы человека.
- Названия факторов сохраняются в решении на момент расчёта: старые заявки показывают старые тексты, проверять на новых.
- Docker Hub рвёт загрузки — `docker pull mirror.gcr.io/library/<образ>` + `docker tag` (команды в README).
- Бесплатные минуты Actions закончились — репозиторий публичный (D16). Секреты не коммитить: `.env`, `.notify.env`.
- `.env` закрыт настройками доступа — не читать.
- Агентам Codex на ноутбуке Ани: если не находится `uv` — `$env:Path = "$env:USERPROFILE\.local\bin;$env:Path"` и `$env:UV_PYTHON_INSTALL_DIR = "$env:TEMP/a09b-python"`.
- Ответы в чате — коротко и по-русски, подробности — в файлы `docs/`. STATE.md — не больше 60 строк.
- Codex и тимлид на одном ноутбуке — **разные клоны** (у Кати: тимлид — `harkachi_alpha26`, Codex — `harkachi_a07`); общий стенд — через `COMPOSE_PROJECT_NAME=harkachi_alpha26`.
