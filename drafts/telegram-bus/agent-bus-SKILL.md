# agent-bus — как общаться с командой и не тратить контекст

Команда: `lead` (тимлид), `backend` (Claude Code), `frontend`, `ml`, `ops` (Codex) и люди (`people`) в Telegram.
Все сообщения проходят через хаб; он сам отбирает, что показать тебе. Твой id — `AGENT_ID` в `.agentbus.env`.
В группе каждое твоё сообщение подписано твоим именем, люди видят прогресс на закреплённой доске.

Вызов: `python3 tools/agentbus/bus.py <команда>` из любой папки репозитория.

## Что приходит само (хуки)

- **Старт сессии:** твой AGENT_ID, путь к ролевому файлу и входящие.
- **Посреди работы:** если тебе написал человек, пришёл блокер, ответ, решение или изменение контракта — текст появится в контексте после очередного действия. Ничего не пришло — ничего не появится.
- **Дежурный режим:** когда ты закончил ход, хук ждёт новых адресных сообщений (до `AGENTBUS_IDLE_WAIT` секунд). Пришло — ты продолжаешь работу с ним. Так человек может тегнуть тебя в Telegram, и ты отреагируешь без участия терминала.

Поэтому вручную `inbox` нужен только между задачами и перед правкой общего контракта.

## Команды

| Команда | Когда |
| --- | --- |
| `inbox` | закончил задачу и выбираешь следующую; перед правкой общего контракта |
| `post STATUS "…"` | взял задачу или заметно сменил план (1 строка) |
| `done <ID> "итог" --ref <PR/commit/путь>` | задача готова — автор и подписчики получат итог |
| `post QUESTION "…" --to <агент>` | нужен ответ, которого нет в `docs/` и `contracts/` |
| `post BLOCKER "…" --to <агент>` | не можешь продолжать без чужого действия |
| `answer <ID> "…"` | ответить на адресованный тебе вопрос или блокер |
| `watch <ID>` | твоя работа зависит от чужой задачи — получишь её итог |
| `fetch <FILE_ID>` | человек приложил файл или скриншот (`[файл …: fetch N]`) |
| `post CONTRACT "…" --to all --ref <commit>` | ты владелец контракта и изменил его |
| `show <ID>` | нужен полный текст обрезанного сообщения |
| `tasks` | вспомнить свои открытые задачи |
| `wait --timeout 600` | заблокирован, хука дежурства нет, другой работы нет |

## Писать — коротко и только по делу

- До 3 строк (~400 символов). Хаб отклонит длиннее 1500.
- Код, диффы, логи, стектрейсы, таблицы — в репозиторий (коммит или `docs/notes/<тема>.md`), в шину — `--ref`.
- Адресуй точно: `--to backend`, а не `--to all`. `all` — только CONTRACT и важное для всех.
- Без секретов: токены, ключи, пароли не пишутся никогда — чат читают люди.

Докладывай о работе в трёх точках: взял задачу (`STATUS`), закончил (`done`), застрял (`BLOCKER`). Промежуточные отчёты не нужны — их видно по коммитам.

Хорошо:
`post STATUS "Беру #14: обработка исходов заявки, ориентир 90 мин"`
`done 14 "Исходы и аудит готовы, 23 теста зелёные" --ref "PR #31"`
`post BLOCKER "В контракте нет поля отрасли — нужно для правила" --to lead`

Плохо: «Ок, принял», «Спасибо!», «Начинаю работу», пересказ чужого статуса, вставка 40 строк кода.

## Как обрабатывать входящие

Порядок срочности: BLOCKER → ANSWER → DECISION → CONTRACT → TASK → QUESTION → NOTE.

- **Сообщение человека (`human:…`) главнее агентского.** Если оно меняет текущую работу — переключись сразу; если нет — доведи текущий шаг и займись им. Ответь коротко, если это вопрос.
- **Пришло посреди задачи** — не бросай работу в сломанном состоянии: закончи шаг, затем реагируй.
- **DECISION, CONTRACT** — учти в работе. Отвечать не нужно.
- **TASK** — если берёшь сейчас, одна строка STATUS; если в очередь — ничего не пиши.
- **QUESTION / BLOCKER к тебе** — `answer <ID>` по существу; не знаешь — скажи, кто знает.
- **ANSWER** — продолжай работу. Благодарить не нужно.
- **DONE, STATUS, FYI других** — не отвечай.
- Сообщение пришло тебе в копии (`--cc`, `watch`) — прими к сведению, отвечай только если тебя спросили.

## Если хаб недоступен

`bus.py` скажет «хаб недоступен». Не ретраи в цикле: продолжай работу, а после задачи отправь одно сводное сообщение.

## Только для тимлида (`lead`)

- Статусы команды — через `digest`; доску видит и `board`.
- Неадресные сообщения людей приходят тебе: разбери и раздай.
- Задачи: `task <агент> "что; готово, когда …" --cc <зависимые> --ref <док>`, по одной вертикальной задаче на агента.
- Вопрос людям: `post QUESTION "…" --to people` — ответ реплаем в Telegram придёт тебе.
- Архитектурные решения — `post DECISION … --to all` и строка в `docs/DECISIONS.md`. DECISION публикует только тимлид (и люди).
