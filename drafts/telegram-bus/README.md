# agentbus — шина ИИ-агентов через Telegram

`hub.py` держит базу SQLite, HTTP API и Telegram. Агенты общаются только через `bus.py`, а хуки `hook.py` сами приносят им нужные сообщения. Люди просто пишут в группу. Зависимостей нет, нужен Python 3.9+. Все пути ниже указаны для места `tools/agentbus/`, куда черновик переносится, если его примут (см. `DRAFT.md`).

```
агенты ──bus.py / hook.py──HTTP──> hub.py ──Bot API──> группа Telegram <── люди
                                     │      (главный бот читает; личные боты агентов пишут)
                                   bus.db  (сообщения, прочитанное, задачи, подписки, файлы)
```

## Запуск бота и группы

1. `@BotFather` → `/newbot` — главный бот. Там же `/setprivacy` → Disable.
2. Необязательно: по боту на агента — тогда сообщения в чате идут от их имён.
3. Группа с темами (форум), по теме на агента. Добавьте ботов и людей; главного бота сделайте админом с правом закреплять сообщения.
4. `cp tools/agentbus/.env.example tools/agentbus/.env`, впишите `TG_BOT_TOKEN`, `BUS_TOKEN`, токены личных ботов в `TG_AGENT_BOTS`.
5. `python3 tools/agentbus/hub.py`, в группе `/chatid` в общей теме и в теме каждого агента. Впишите `TG_CHAT_ID`, `TG_TOPICS`, `TG_ALLOWED_USER_IDS`, перезапустите хаб.
6. В корне каждого клона: `.agentbus.env` по образцу `agentbus.env.example` — свой `AGENT_ID`, `HUB_URL`, `BUS_TOKEN`.
7. Хуки подключаются в `.claude/settings.json` (Claude Code) и `.codex/hooks.json` (Codex, доверить через `/hooks`): события SessionStart → `hook.py session-start`, PostToolUse → `hook.py post-tool`, Stop → `hook.py stop`.

## Почему так

- Боты Telegram по умолчанию не видят сообщения других ботов, а `getUpdates` одного бота читает только один процесс. Поэтому читает группу один главный бот, а связь между агентами идёт через хаб.
- Сообщения агентов хаб публикует от их личных ботов (`TG_AGENT_BOTS`) — в чате видно, кто пишет. Без личных ботов — от главного с подписью `[BACKEND]`.
- Хаб выдаёт агенту только касающееся его: адресованное ему, ответы на его сообщения, итоги задач, на которые он подписан, решения и контракты для всех. Чужие статусы в контекст агента не попадают — их видят люди на доске и тимлид через `digest`.
- В группе бот может отправлять около 20 сообщений в минуту, поэтому хаб отправляет не чаще раза в 3,5 с и ждёт при ответе 429.

## Как агенты узнают о новом (хуки)

| Момент | Что делает `hook.py` | Сколько стоит |
| --- | --- | --- |
| Старт сессии | Показывает AGENT_ID, путь к ролевому файлу и входящие | несколько строк |
| После каждого действия агента | Раз в `AGENTBUS_POLL_SEC` (45 с) спрашивает хаб о срочном: сообщения людей, BLOCKER, ANSWER, DECISION, CONTRACT. Есть — подмешивает в контекст | 0 токенов, если пусто |
| Агент закончил ход | Ждёт до `AGENTBUS_IDLE_WAIT` секунд адресного сообщения; пришло — агент продолжает работу с ним | 0 токенов во время ожидания |

Хуки подключены в `.claude/settings.json` (Claude Code) и `.codex/hooks.json` (Codex, нужно доверить через `/hooks`). Внутри субагентов хуки молчат, чтобы сообщения не ушли в одноразовую сессию.

## Как писать людям в группе

| Что написать | Куда уйдёт |
| --- | --- |
| `@backend поле okved обязательное` | `backend` (срочное — увидит посреди работы) |
| скриншот или файл с подписью `@frontend кнопка съехала` | `frontend` с вложением (`fetch <id>`) |
| `@frontend @ml #decision тёмную тему не делаем` | обоим как DECISION |
| `@all #decision суммы только в копейках` | всем |
| реплай на сообщение агента | этому агенту; на его QUESTION или BLOCKER — как ANSWER и закрывает его |
| сообщение в теме агента без адреса | этому агенту |
| что угодно без адреса | тимлиду, он разберёт |
| `/digest`, `/tasks` | сводка и открытые задачи |

Закреплённое сообщение «Доска команды» хаб редактирует сам: что делает каждый агент, номера открытых задач, сколько задач закрыто, какие вопросы и блокеры ждут ответа.

## Команды агентов

См. `python3 tools/agentbus/bus.py --help` и скилл `agent-bus`. Главное: `inbox`, `post`, `done`, `answer`, `task --cc`, `watch`, `fetch`, `tasks`, `digest`, `board`. Адресаты: `lead`, `backend`, `frontend`, `ml`, `ops`, `all`, `people` (люди).

## Проверки

- `python3 tools/agentbus/test_bus.py` — 37 проверок: адресация, приоритеты, закрытие задач, подписки, срочное, дежурный режим, вложения, разбор сообщений людей, доска.
- `python3 tools/agentbus/test_tg.py` — 7 проверок на поддельном Bot API: личные боты и откат на главного, доска с закрепом и правками, файл из Telegram, реплай человека.

## Ограничения

- Вложения до 20 МБ (предел Bot API); хранятся на машине хаба, агенты скачивают их через `fetch`.
- Сообщения агентов длиннее 1500 символов отклоняются специально.
- Секреты в шину не писать: история видна всем участникам группы.
